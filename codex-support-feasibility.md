# Codex support in AgenC: feasibility assessment

Read-only exploration. Source at `main` `90e0ed6` (mission clone). Codex CLI `codex-cli 0.153.4` at `/opt/homebrew/bin/codex`. Every `path:line` below was read this session; every Codex claim is quoted from a command run this session or a docs URL.

Provenance: AgenC mission `c7ff49d6-47c6-4453-8573-42ff7a258587`; builds on mission `e92f8167-e41e-4bb4-8913-1839f75ee059` (Codex MCP/exec probes). No code, `~/.claude`, or `~/.codex` config was changed. Side effect disclosed in section 6.

## 0. One-paragraph answer

Swapping the spawned binary is a few lines. The brief's hypothesis ("the expensive part is everything downstream") is **half wrong**: two of the downstream couplings that looked hardest turned out cheap, because Codex 0.153.4 ships a hooks system that reuses Claude Code's event names and stdin JSON shape, and accepts per-invocation config overrides via `-c key=value`, which together replace `--settings op-settings.json`. What stays genuinely expensive is **transcript discovery and parsing**: five call sites locate a mission's transcript through a Claude-only `~/.claude/projects/<encoded-cwd>/<uuid>.jsonl` convention, and four independent parsers dispatch on Claude's `{"type":"user"|"assistant","message":{...}}` line shape, none of which exists in Codex's rollout format (which Codex itself calls "legacy" and is migrating to SQLite). Two further hard walls: the interactive TUI shows a **blocking folder-trust dialog** that `-c` overrides did not suppress (AgenC would have to write into `~/.codex/config.toml`, mirroring today's `~/.claude.json` seeding), and there is no Codex analogue of Claude's live session registry, so `mission peers` cannot work.

## 3. Verdict

**Size: L for full parity; M for the cheapest useful subset.** Rough hours (one experienced engineer, this codebase, including E2E per `CLAUDE.md`):

- Cheapest useful subset (interactive Codex missions with idle/busy tracking, prime injection, reload with prompt, send-keys, headless exec; no transcript features): **M, ~2 to 3 days (16 to 24 h)**. Change surface: 1a, 1b, 1c, 1d, plus a minimal 1e stub that records `transcript_path` from the hook stdin into the mission (a new `agenc mission send claude-update` field) so `GetLastSessionID`/resume work for Codex without scanning `~/.codex/sessions`. Trust: write `projects.<agentDir>.trust_level="trusted"` into `~/.codex/config.toml` at create, mirroring `seedMissionTrust`; or accept a one-time dialog per mission.
- Full parity (session print text, search index, auto-summary, custom titles, peers): **L, roughly 5 to 8 days (40 to 64 h)**, dominated by a second transcript adapter behind an interface for 1e, and blocked on the rollout-format deprecation.

**Genuine blockers (not effort, but walls):**

1. **Rollout format is declared legacy by Codex itself** (`codex migrate-rollouts`: "migrate legacy local sessions to paginated thread history"). Any parser written against `rollout-*.jsonl` is coupling to a format on its way out; the successor is SQLite (`thread_history_1.sqlite`) with no documented read API found this session. The durable per-mission signal is the hook stdin (`transcript_path`, `last_assistant_message`, `prompt`), not the file.
2. **Interactive trust dialog** blocks every new-directory TUI spawn, and the per-invocation override `-c 'projects."/private/tmp".trust_level="trusted"'` as spelled did not suppress it (whether Codex consults `-c` for trust at all, or whether the dotted key parsed, was not established). Likely requires writing user config (`~/.codex/config.toml`) from the server, the one thing the brief's constraints and AgenC's State Y posture try to avoid for Claude too (yet already do via `~/.claude.json`).
3. **Hooks only run with `--dangerously-bypass-hook-trust`** when delivered per-invocation; Codex prints a warning line into the session each spawn. Alternative (persisted trust for a `~/.codex/hooks.json`) means AgenC-managed content inside `~/.codex`.
4. **No peers/registry**, so `mission peers` and `formatPeerAddress` degrade to "no peer" for Codex missions. Not fixable from AgenC's side.
5. **`PostToolUseFailure` and `Notification` do not exist**; `needs_attention` must be rebuilt on `PermissionRequest`, whose stdin shape was not exercised this session (no approval was requested under `-a never`).

**Cheapest viable subset, concretely:** `--agent codex` -> persisted column -> `BuildAgentCmd` switch that emits `codex --dangerously-bypass-hook-trust -s workspace-write -a on-request -c model_reasoning_effort=<effort> -c 'hooks.Stop=[...]' -c 'hooks.UserPromptSubmit=[...]' -c 'hooks.PostToolUse=[...]' -c 'hooks.PermissionRequest=[...]' -c 'hooks.SessionStart=[agenc prime]' [-m model] [resume <id>] [PROMPT]`; wrapper `handleClaudeUpdate` gains `PermissionRequest`; `send claude-update` learns to forward `transcript_path`; mission row stores the current rollout path; `GetLastSessionID` reads it for Codex. Transcript-derived features are declared unsupported for Codex missions (search index, titles, auto-summary, `session print --format=text`).

## 4. Hypothesis check (brief asked to falsify)

"The expensive coupling is not process spawning but everything downstream (transcript format, hooks, settings injection, state detection)."

- **Right** on spawn being trivial (`mission.go:66-124`, `wrapper.go:276-296`).
- **Wrong** on hooks and settings injection: Codex's hook events, stdin JSON, and `additionalContext` return mirror Claude Code's closely enough that `overrides.go:54,61` command strings and `wrapper.go:393-422` state switch carry over; per-invocation `-c` overrides replace `--settings`. State detection (idle/busy) therefore also carries over. Cost here is a TOML renderer plus two event-name edits, not a redesign.
- **Right** on transcript format and discovery: 1e is the bulk of the work and is the only part with an external deprecation hanging over it.
- **Missed** two couplings the hypothesis did not name: the TUI folder-trust dialog (section 2) and the absent session registry (peers).
